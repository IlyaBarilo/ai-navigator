# Для разработчика

[Описание проекта](../README.md) · [Условия частей проекта](../NOTICE.md)

## Сборка

Нужен Node.js 20 или новее. Пользователю готового HTML Node.js не требуется. Сборка использует стандартную библиотеку Node.js.

В Git коммитятся только исходники, документы и ресурсы из PUBLIC-FILES.json. Готовый ai-navigator.html создаётся локально или в Actions и в коммит не включается.

Обычные правки делайте в `src/`. `ai-navigator.html` — результат сборки; JavaScript, CSS и разметку в нём вручную не меняйте.

Если отдельно редактировался разрешённый блок `catalog-data` готового HTML, сначала импортируйте эти изменения. Не выполняйте импорт поверх более новых правок `src/catalog.json`: сначала сопоставьте обе версии.

```cmd
node tools/import-html.mjs
```

Затем соберите файл:

```cmd
npm run build
```

Результат — `ai-navigator.html`: данные, стили, код, иконка и лицензионные тексты. Не нужны внешние шрифты, сервер, API или загрузка библиотек при запуске.

Старый файл с другим именем также можно импортировать, передав его путь аргументом `tools/import-html.mjs`. Импорт переносит только JSON, не выполняя код HTML.

| `src/app/search.js`, `src/app/filters.js` | Разбор запросов и правила подбора |
| `src/app/state.js`, `src/app/theme.js` | Настройки, ссылки, тема и масштаб |
| `src/app/results.js`, `src/app/dialogs.js` | Карточки, результаты и подробности |
| `src/app/expert-controls.js`, `src/app/prompts.js` | Элементы Эксперта и редактируемые примеры |
| `src/app/simple.js`, `src/app/training.js` | Простой режим и пять шагов обучения |
| `src/app/navigation.js`, `src/app/start.js` | Переключение режимов и запуск |
| `src/style.css`, `src/styles/*.css` | Порядок стилей; базовые элементы, темы, каталог, обучение, адаптивность, Простой режим |
| `src/appearance.css` | Утверждённое оформление и общие типографические роли |
| `src/icons.svg`, `src/background.svg` | Обычные значки и векторный фон |

| `LICENSE`, `NOTICE.md`, `BRANDING.md`, `EDUCATIONAL-MATERIALS.md` | Источники правовых текстов для сборки; учебные примеры имеют отдельные условия |

Комментарии `@include` обрабатывает `tools/source-bundle.mjs` во время сборки. Это части одного скрипта с общей закрытой областью, не отдельные загружаемые браузером модули. Порядок задан в `src/app.js`; начальные действия находятся в `start.js`. Стили идут в порядке `src/style.css`, затем применяется `appearance.css`. Не переставляйте части без проверки зависимостей и каскада. Разметка собирается по включениям из `template.html`.

Сборщик использует только стандартный Node.js. Отступы — два пробела, переносы — LF. Новый исходник внесите в `PUBLIC-FILES.json` после проверки; один файл не должен подключаться повторно. В готовом HTML включений и внешнего загрузчика нет.

Карточка описывает сервис, приложение или агента. Цена, режим, качество, сложность, доступность, источники и аппаратные требования задаются у каждой функции. Не объединяйте платное качество одной функции с бесплатным доступом другой. Указание источника не заменяет проверку актуальных условий.

Необязательные `displayLabel` и `displayIcon` у функции задают её видимую подпись и встроенный значок отдельно от `category`, используемой в подборе. Так функцию программирования можно показывать как «Код», сохраняя её правила поиска и отдельную оценку. `variant` уточняет режим под подписью. Значок должен существовать в `src/icons.svg`; сборка и чтение каталога проверяют эти поля.

`quality.level` — целое число от 1 до 5 либо явное `null`, если качество пока не оценено. Для `null` показывается текст без звёзд и числового балла; порог качества от 1 и выше исключает такую функцию. В сортировке по качеству она следует после оценённых функций; в рекомендуемом порядке сохраняется приоритет группы доступа. `null` не является нулевой оценкой. Сложность по-прежнему задаётся целым числом от 1 до 5. Описание функции и источники не заменяют практическую оценку результата.

Необязательные `subjectAliases` у функции ограничивают точный подбор явно заданным предметным контекстом. Функция остаётся доступна в полном каталоге без фильтра задач и при поиске названия без дополнительной задачи. Свободная тема Простого проверяется по исходному запросу, даже когда общий текстовый подбор временно использует пустую строку. Старые функции без поля сохраняют прежний подбор. У примера `forTools` задаёт связанные ID продуктов: он доступен при поиске связанного продукта без задачи либо вместе с задачей этого примера. Пример с `subjectAliases` также доступен в своей задаче при совпавшем предметном контексте, даже без названия продукта. Сборка и чтение каталога проверяют поля; постоянные коды прежних примеров сохраняются.

Необязательный `delivery` описывает получение результата: `outputs[]` содержит `format`, `method`, `editable` (`yes`, `no`, `unknown`) и ссылки `sources` на справочник источников; `requirements` и `note` поясняют необходимые действия и ограничения. Пустой `outputs` означает, что конкретный формат не подтверждён. Форматы и поисковые формулировки задаются в `search.presentation`. Поддерживаются способы `download`, `save-code`, `browser-print`, `integration`, `local-build`, `web`. Сборка и чтение данных проверяют их значения. Старые каталоги без новых полей продолжают открываться.

Точное требование формата презентации проверяется на одной подходящей функции, вместе с доступом, регионом и оценками. Несколько явно запрошенных форматов должны быть у этой же функции. Для редактируемого результата `unknown` не равен `yes`; для скачивания файла печать браузера и сохранение кода не считаются прямым экспортом. Формат после «из»/«по» обозначает исходник, не выход; загрузка такого исходника этим фильтром не подтверждается. Наличие формата не изменяет авторский балл качества. Входные материалы `src_input/`, как и `local/`, не входят в публичную поставку.

Идентификаторы и ключи `barilo.ai-catalog.*` обеспечивают совместимость ссылок и настроек. Их изменение требует миграции. Полный редактируемый учебный запрос не должен сохраняться в постоянной памяти браузера.

В `tasks[].prompts[]` поле `code` — постоянный уникальный код вида `P001`, `revision` — целая положительная версия исходного текста. Новому примеру назначают следующий свободный код; существующие коды не перенумеровывают и не используют повторно после удаления. При изменении текста запроса увеличивают `revision`, сохраняя `code`. В интерфейсе показывается обычный выделяемый текст «Пример: 1» без служебного префикса и версии, перед стрелками перелистывания; номер получают из `code`, он одинаков во всех режимах; редактирование поля пользователем не меняет версию исходного примера. Сборка проверяет формат и уникальность кодов. Чтение старых каталогов без этих полей сохраняется: для них номер определяется положением примера в полном списке.

## Проверки

Установите зависимости и тестовый браузер:

```cmd
npm ci
```

```cmd
npm run browser:install
```

Проверьте состав и пользовательские сценарии:

```cmd
npm run check:public
```

```cmd
npm run verify:all
```

Отчёты создаются в `local/qa/`, браузер — в `local/browser-cache/`. Эти каталоги не нужны заранее и не входят в поставку. Переменная `AI_NAVIGATOR_BROWSER_PATH` позволяет использовать установленный совместимый браузер. В Linux CI системные библиотеки устанавливаются командой `npx playwright install --with-deps chromium`.

`PUBLIC-FILES.json` определяет состав исходной поставки. `check:public` проверяет структуру и отсутствие закрытых путей без частных материалов. Дополнительная редакционная проверка владельца выполняется до передачи публичных файлов; она не заменяется общими тестами.

## GitHub Pages

Подготовить локальный комплект сайта:

```cmd
npm run build:pages
```

Команда собирает `ai-navigator.html` и помещает комплект в `local/pages/`. В нём только два файла:

- `ai-navigator.html` — побайтовая копия автономной программы.
- `index.html` — небольшая входная страница для корня сайта. Она открывает `ai-navigator.html`, сохраняя строку параметров и якорь с выбранным режимом. При выключенном JavaScript остаётся ссылка перехода.

`index.html` существует только внутри комплекта Pages; основное имя сборки и скачивания — `ai-navigator.html`. Относительный переход работает как под путём репозитория, так и в корне собственного домена. `npm run prepare:pages` упаковывает уже собранный и проверенный HTML без повторной сборки.

В настройках репозитория автор выбирает **Settings → Pages → Build and deployment → Source → GitHub Actions**. Окружение `github-pages` следует ограничить веткой `main`. Workflow «Проверки и Pages» после push в `main` собирает программу, проверяет её, загружает только `local/pages/` и выполняет развёртывание. Задание развёртывания зависит от успешной проверки; исходники, зависимости и частные файлы в сайт не включаются.

Проверка `npm run verify:pages` входит в `verify:all`: поднимает локальный HTTP-сервер, проверяет корень и прямой адрес файла, параметры/якоря, режимы и отсутствие дополнительных запросов приложения. Публикация в GitHub этим тестом не выполняется.

`npm run verify:helper` также входит в `verify:all`: проверяет мобильные подсказки, ручную прокрутку к целям, отключение двумя кнопками, сохранение настройки помощника вместе с темой и доступностью, работу без хранилища и приглашение к обучению. Снимки и отчёт создаются в `local/qa/helper/`.

`npm run verify:guided` проверяет три экрана режима «По шагам», переходы вперёд и назад, сохранение описания и доступа, обучение над результатами, пустую выдачу, прямые ссылки и автономный перенос. Входит в `verify:all`; отчёт и снимки — `local/qa/guided/`.

После включения Pages ожидаемый адрес этого репозитория — `https://ilyabarilo.github.io/ai-navigator/`; до успешного развёртывания его доступность не гарантируется. Онлайн-страница обновляется после публикации изменений, скачанные копии — только при повторном скачивании. Настройки браузера для локального файла и сайта могут храниться отдельно.

## Выпуски

Проверки GitHub Actions запускаются после отправки изменений в `main`. Выпуск создаётся в GitHub Releases кнопкой **Publish release**. Workflow получает точный тег опубликованного Release, проверяет его принадлежность истории `main`, собирает HTML и проверяет его перед прикреплением файлов.

Для задания выпуска требуется окружение `release` с правилом **Selected branches and tags → Tag → `v*`**. Обычные проверки `main` не используют это окружение. Отдельный ручной запуск Actions не требуется.

Допустимы числовые теги с одной–четырьмя частями: `v1`, `v0.1`, `v0.1.0`, `v0.1.2.3`. Номер сохраняется строкой. В готовом выпуске он показан в окне «Лицензии и название» и сохраняется при открытии скачанного файла без сети.

После успешной сборки к Release прикрепляются `ai-navigator.html`, HTML с номером выпуска в имени и `SHA256SUMS.txt`. Первый файл удобен для ссылки на последнюю версию, второй — для закрепления конкретного учебного примера. Условия лицензирования встроены в оба HTML. Архивы Source code содержат исходники; готовый релизный HTML не требует сборки.

Описание выпуска — короткий маркированный список изменений для пользователя. Готовые файлы доступны после завершения задания сборки.
